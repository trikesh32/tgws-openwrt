# Cloudflare Worker для tgws

Начиная с 0.1.3 (резервный режим — с 0.1.4), tgws умеет передавать исходный TCP-поток Telegram через
Cloudflare Worker. На телефонах, компьютерах и в Telegram настройки не нужны.
Маршрут: устройство → роутер → WSS/443 → Worker → исходный IP и TCP-порт Telegram.
Этот путь подходит для сообщений и медиа; UDP-звонки он не переносит.

## Создание Worker через браузер

1. Зарегистрируйтесь на https://dash.cloudflare.com/sign-up и подтвердите почту.
2. Откройте **Workers & Pages**, создайте Worker из **Hello World**.
3. Откройте **Edit code**, замените содержимое основного файла полным содержимым
   [`worker.mjs`](worker.mjs) из этого каталога и нажмите **Deploy**.
4. Создайте случайный секрет локально. На macOS/Linux: `openssl rand -hex 32`.
   На Windows PowerShell:

   ```powershell
   $bytes = New-Object byte[] 32
   $rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
   $rng.GetBytes($bytes)
   $rng.Dispose()
   -join ($bytes | ForEach-Object { $_.ToString('x2') })
   ```

5. В настройках Worker, **Variables and Secrets**, добавьте переменную типа
   **Secret** с именем `TGWS_TOKEN` и этим значением. Сохраните и разверните
   изменение. Это ваш отдельный секрет доступа, **не API-токен Cloudflare**.
6. Скопируйте домен Worker, например `tgws-relay.example.workers.dev`.
7. На роутере откройте **Службы → Telegram → Настройки → Cloudflare Worker**.
   Введите домен без `https://` и пути, а также тот же секрет. Оставьте режим
   **Резервный** для начальной проверки. Для [проверенной схемы с zapret2](../RESULTS.ru.md)
   выберите **предпочитать Worker** (`prefer`). **Сохранить и применить**.
8. В диагностике tgws выполните проверку связи. Она отправляет настоящий
   MTProto-запрос к DC2 и DC4 через Worker, а не просто проверяет HTTP-ответ.
   Затем перезапустите Telegram и проверьте загрузку фото и видео. На странице
   состояния должен увеличиваться счётчик **Через Cloudflare Worker**.

До настройки секрета Worker отвечает 401, а его главная страница — 404: это
ожидаемо. Открытие домена в браузере не проверяет связь с Telegram.
Проверьте доступные квоты и тариф своего аккаунта в панели Cloudflare;
платный тариф автоматически не подключается этим проектом.

Рабочий опыт на AX3000T: [результаты, TLS-профиль и ограничения](../RESULTS.ru.md).
Worker без TLS-стратегии в этой сети тормозил; сочетание с ней прошло короткую проверку.

## Поведение и совместимость

- Пустое поле домена отключает Worker и сохраняет прежнее поведение tgws.
- В режиме `fallback` (по умолчанию с 0.1.4) сначала используется прежний Telegram
  WebSocket; Worker пробуется перед прямым TCP, если этот путь недоступен или
  неприменим. Режим `prefer` направляет все перехваченные TCP-соединения сначала
  через Worker. На некоторых сетях это ухудшает загрузку чатов даже при успешной
  короткой проверке: выбирайте резервный режим и проверяйте реальные загрузки.
- Адрес назначения Worker берётся из исходного соединения; таблица `DC → IP`
  для самого Worker не нужна. Уже прочитанное приветствие передаётся без изменений.
- Если DNS/TLS/WebSocket или подключение Worker к Telegram не установились,
  tgws пробует прежний путь Telegram WebSocket/прямой TCP. Неудачный адрес
  пропускается на одну минуту, чтобы не задерживать каждый повторный запрос.
- После начала передачи соединение нельзя безопасно переиграть через другой
  путь; при обрыве Telegram должен открыть новое соединение.
- `dc_ip` и `ip_dc` продолжают управлять прежним маршрутом. Не удаляйте рабочие
  значения при включении Worker.
- С исходным Worker Flowseal `/apiws?dst=IP` соединение совместимо, поле секрета
  нужно оставить пустым. Однако он всегда подключается к TCP/443 и не проверяет
  адрес назначения. Для сохранения портов 80/443/5222 и ограничения доступа
  используйте Worker из этого каталога.
- Worker принимает только адреса из перечисленных в коде публичных IPv4-подсетей
  Telegram и порты 80/443/5222. Произвольные домены и внутренние IP запрещены.
  Если Telegram добавит подсети, обновите список и на роутере, и в Worker.
- Проверка сертификата TLS обязательна. Секрет передаётся заголовком Authorization,
  не в URL, не в командной строке и не в счётчиках LuCI. На роутере он хранится
  в закрытом UCI-конфиге и временном файле, доступном службе только для чтения.
- Запросы WS проверяют секрет до открытия исходящего TCP. Очередь записей в TCP
  ограничена 1 МиБ, размер входного сообщения — 256 КиБ, простой — 5 минут.
  Используется стандартный WebSocket API Workers; отдельного прикладного
  протокола подтверждений для ограничения очереди ответов Cloudflare нет.
- Cloudflare завершает внешний TLS и пересылает байты Telegram. Шифрование
  Telegram сохраняется, но Cloudflare видит сетевые метаданные.

Если домен Worker недоступен у провайдера, сам этот путь не заработает.
Отдельно проверяйте DNS, TLS и правила zapret; пакет не меняет их автоматически.

## CLI и развёртывание через Wrangler

```sh
tgws -worker-domain tgws-relay.example.workers.dev -worker-mode fallback -worker-token-file /path/to/secret
tgws -probe -worker-domain tgws-relay.example.workers.dev -worker-token-file /path/to/secret
```

Для установленного и настроенного сервиса временный файл находится в
`/var/run/tgws-worker.token`. Его значение не нужно выводить в журнал.

Из каталога `worker`, с уже установленным Wrangler и авторизованным аккаунтом:

```sh
wrangler secret put TGWS_TOKEN
wrangler deploy
```

Проверки без аккаунта и без развёртывания:

```sh
node --experimental-vm-modules --test worker/worker.test.mjs
go test -race ./...
```

Worker использует протокол из
[инструкции Flowseal](https://github.com/Flowseal/tg-ws-proxy/blob/main/docs/RU/CfWorker.md).
Реализация в этом каталоге добавляет авторизацию, проверку адресов, сохранение
порта, последовательные записи и обработку ошибок до WebSocket Upgrade.
Справка Cloudflare: [TCP sockets](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/),
[Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
