# tgws для OpenWrt

Поддержка Cloudflare Worker (с версии 0.1.3): [создание и настройка](worker/README.ru.md).

> Форк [NooBiToo/tgws-openwrt](https://github.com/NooBiToo/tgws-openwrt), исходная база `f64036d`.
> Доработки безопасности готовятся к версии **0.1.2**. До публикации тега и релиза команды
> установки ниже не работают: старые релизы без контрольных сумм намеренно не принимаются.
> Обход сообщений проверен на AX3000T с OpenWrt 25.12.6. Звонки этим обходом не исправлены.

## Доработки безопасности форка

- Пакеты MTProto больше 2 МиБ, нулевые длины и повреждённые заголовки закрывают соединение.
  Это ограничение для роутера, а не объявленный максимум протокола Telegram; необычно
  большие контейнеры будут отклонены. Файлы передаются частями, а не одним пакетом.
- Вместимость двух буферов сборки ограничена общим бюджетом 16 МиБ на процесс.
  Бюджет освобождается при разрыве, ошибке и неудачном определении DC.
- Не более 64 одновременных соединений и 16 с одного IP. Ожидание ввода/вывода —
  до 5 минут, записи в WebSocket — до 30 секунд. Карты адресов также ограничены.
- Служба работает как `tgws:tgws` в обязательной изоляции `procd-ujail` с
  `no_new_privs` и единственной capability `CAP_NET_RAW` для SO_MARK (Linux 5.17+).
  Права на изменение firewall остаются у init-скрипта, не у демона.
  Доступен только отдельный каталог статистики для записи; сертификаты — для чтения.
  При отсутствии изоляции служба отказывается запускаться. Порт должен быть >=1024.
- Лимит файловых дескрипторов — 256, core dump выключен, `GOMEMLIMIT=64MiB`.
  **GOMEMLIMIT — мягкий ориентир GC, не жёсткий предел RSS.** Бюджет сборки также
  не включает TLS, WebSocket, стек и память сокетов ядра.
- WebSocket требует корректный `Sec-WebSocket-Accept`; длина строк заголовков ограничена.
- Установка требует явного `TGWS_VERSION` и проверяет SHA-256 всех загруженных
  файлов **до** остановки старой службы и замены бинарника. Релизы публикуют SHA256SUMS.
  Манифест получен с того же GitHub: это проверка целостности, не независимая подпись.
  `apk --allow-untrusted` остаётся для локального пакета, уже проверенного по манифесту.
  Компрометацию аккаунта издателя эти суммы не исключают.

Проверки: `go test -race ./...`, `go vet ./...`, `sh tests/run.sh`;
регрессионные тесты больших/разбитых заголовков, общего бюджета, повторного освобождения,
параллельных соединений, таймаутов, отказа без jail и повреждённых артефактов.
Кросс-сборка: `sh scripts/build.sh dist`. Работа Telegram и запуск ujail на целевом
OpenWrt требуют отдельной проверки перед эксплуатацией.

**Telegram на всех устройствах домашней сети идёт через WebSocket — без настройки на самих устройствах. Управление и диагностика в LuCI.**

`luci-app-tgws` запускает на роутере с **OpenWrt 25.12+** прозрачный прокси для Telegram.
Роутер перехватывает соединения устройств к дата-центрам Telegram и проводит их через WebSocket
(`kws*.web.telegram.org`) — туда, где прямое соединение медленное или заблокировано. Прокси, secret
и ссылки `tg://proxy` на телефонах и компьютерах настраивать не нужно.

- **Прозрачно:** правило `nftables` перенаправляет трафик на локальный демон; клиенты ничего не знают.
- **Не ломает Telegram:** если WebSocket недоступен, байты клиента дословно повторяются прямым соединением.
- **Настройка в браузере:** три страницы в LuCI — состояние, настройки, диагностика.
- **Настоящая диагностика:** не «порт открыт», а реальный запрос к каждому дата-центру с замером времени и подсказкой, что чинить.
- **Android и Desktop:** для Android, который не называет дата-центр в соединении, он определяется автоматически.
- **Дружит с TrustTunnel:** то, что нельзя провести через WebSocket (веб-страницы Telegram и т. п.), можно отправить через ваш туннель.

Идея и детали протокола — проект [Flowseal/tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy); здесь это
самостоятельная реализация на Go, которая работает на роутере прозрачно.

## Как это работает

```
устройство в LAN ─TCP→ адрес дата-центра Telegram
                          │  nftables: redirect на локальный порт
                          ▼
                        tgws (на роутере)
                          ├─ WebSocket (TLS) → kws{N}.web.telegram.org
                          └─ если WebSocket недоступен — прямое соединение (или через туннель)
```

Роутер снимает и накладывает только транспортную обфускацию соединения. Сообщения Telegram остаются
зашифрованными его собственным протоколом от клиента до сервера, и роутер их не читает.

## Быстрый старт

### Что понадобится

- Роутер с **OpenWrt 25.12 или новее**, LuCI и пакетным менеджером `apk`.
- Доступ по SSH и около 5 МБ свободного места под бинарник.
- Готовые APK сейчас собираются для `aarch64_cortex-a53` (включая AX3000T).
  Проверить архитектуру: `. /etc/openwrt_release; echo $DISTRIB_ARCH`.
  Для остальных архитектур доступны исходники и кросс-сборка бинарников; установщик
  требует APK для точной архитектуры и отказывается от установки, если его нет.

OpenWrt 24.10 и более ранние версии с `opkg` не поддерживаются.

### 1. Установите пакет

Выполните по SSH **на роутере**:

```sh
TGWS_VERSION=v0.1.2 sh -c "$(wget -O - https://raw.githubusercontent.com/trikesh32/tgws-openwrt/v0.1.2/install.sh)"
```

Установщик проверит совместимость и SHA-256, затем одной транзакцией `apk` поставит
`tgws` (бинарник), `luci-app-tgws` (служба, конфиг, интерфейс) и русский перевод.
Бинарник больше не копируется вне пакетного менеджера; `/etc/config/tgws` сохраняется
как конфигурационный файл при обновлении.
При первой установке служба сразу включается; чтобы оставить её выключенной, запустите установщик с `TGWS_ENABLE=0`.
При обновлении текущее состояние (включена или выключена) не меняется.

### 2. Настройте ускорение

Если служба выключена (установка с `TGWS_ENABLE=0` или вы отключили её сами), включите её:
**Службы → Telegram → Настройки → Включить → Сохранить и применить**.

Дополнительно:

- Если у вас [TrustTunnel](https://github.com/NooBiToo/TrustTunnelOpenWrt) и прямой доступ к Telegram закрыт,
   на вкладке **Остальной трафик** выберите туннель (`0x9527`): через него пойдёт то, что нельзя
   провести через WebSocket.

### 3. Проверьте результат

Откройте **Диагностика** и нажмите **Запустить проверки**, затем **Проверить связь**.
На странице **Состояние** растёт счётчик «Через WebSocket», когда вы пользуетесь Telegram.
Перезапустите приложение Telegram на устройстве: уже установленные соединения не перенаправляются.

## Что важно знать

- Перехватывается только **IPv4**. Если на роутере включён IPv6, клиент может обойти ускорение по IPv6;
  диагностика предупредит об этом.
- WebSocket по умолчанию открывается для **DC2 и DC4**. Остальные дата-центры и веб-страницы Telegram
  идут напрямую либо, если задана метка, через туннель TrustTunnel.
- Клиенты с **прокси или VPN** в перехват не попадают: отключите прокси в настройках Telegram.
- Зона файрвола каждой сети, которую вы перехватываете, должна принимать входящий трафик к роутеру
  (`input ACCEPT`), иначе из неё Telegram не подключится. Для обычной сети `lan` это так.
- Если в списках TrustTunnel выбран Telegram, этот трафик туда не попадёт: перехват срабатывает раньше.
- `/etc/init.d/firewall stop` снимает все таблицы `nftables`, включая нашу; верните перехват командой
  `/etc/init.d/tgws restart`.
- Проверено на Android и Windows Desktop; **iOS не проверялся**.

Полный список особенностей — в [ограничениях](GUIDE.ru.md#ограничения).

## Сборка APK

Workflow `Release` можно запустить вручную: он собирает статические бинарники из
того же коммита, затем пакеты в официальном SDK OpenWrt 25.12.6 mediatek/filogic.
Результат — артефакт `package`; запуск без тега не публикует GitHub Release.
`luci-app-tgws` зависит от `tgws`. Бинарник учитывается в `apk info -W /usr/bin/tgws`.
Для ручной SDK-сборки сначала выполните `TGWS_VERSION=0.1.2 sh scripts/build.sh dist`,
подключите корень проекта как feed `tgws` и соберите `tgws` и `luci-app-tgws`.
Путь к готовым бинарникам можно задать make-переменной `TGWS_PREBUILT_DIR`.
